# KIC AI 에이전트 공모전 기획서 — 지배구조·원인 역추적 에이전트 (가칭)

Oct 17, 2026 · @valentine

## 1. 프로젝트 개요

실무자가 투자 대상의 실제 지배구조를 빠르게 추적하고, 모든 연결에 근거 문서를 붙여 보여주는 AI 에이전트다. 사람이 며칠 걸리던 소유 관계 확인을 자동화하고, 확인하지 못한 구간은 숨기지 않고 "여기서 막힘"으로 표시한다.

- **메인 기능**: 지배구조 역추적(Beneficial Owner Back-tracer). 기업명만 넣으면 최대주주와 상위 법인을 따라 올라가며 소유 그래프를 만든다.
- **보조 모듈**: 이벤트 원인 추적(Event Root-Cause Tracer). 보유 자산에 이상 이벤트가 생기면 관련 공시·뉴스를 묶어 원인 후보를 제시한다.
- **타깃**: 투자 실사와 모니터링을 하는 실무자. 개인투자자용 범용 서비스는 이번 범위에서 제외한다.
- **데모 방식**: 실제 상장사 데이터로 시연한다. 금융에서는 검증 가능한 근거가 신뢰의 전제이기 때문이다.

| 공모 조건 | 이 기획의 대응 |
| --- | --- |
| 사람이 못 하거나 오래 걸리는 일 | 다단계 지분 구조 추적과 근거 문서 대조를 자동화 |
| 오케스트레이션 + 여러 도구 | 오케스트레이터가 DART·GLEIF·SEC·Companies House 도구를 라우팅 |
| 오픈소스·라이선스 문제 없음 | 무료 공개 API 중심 구성 (소스별 약관은 구현 전 확인) |
| 블루오션 | 공시·글로벌 레지스트리·문서를 한 흐름으로 잇는 실무용 도구를 지향 |

## 2. 배경과 문제 정의

KIC의 투자 대상은 여러 국가의 다단계 법인 구조에 걸쳐 있어서, "이 자산을 실제로 누가 지배하는가"를 확인하는 데 드는 시간이 실사의 큰 병목이다.

- **KIC 규모**: 정부와 한국은행 등에서 위탁받은 외환보유고를 해외 자산에 투자한다. 2024년 말 기준 약 2,065억 달러를 67개국에 분산했다 ([자소설닷컴 기업분석, AI 요약 기반](https://jasoseol.com/companies/620/insights)).
- **투자 자산군**: 글로벌 주식, 채권, 사모펀드, 부동산, 인프라.
- **네트워크**: 서울 본사 외에 뉴욕·런던·싱가포르 지사, 샌프란시스코·뭄바이 사무소.

아래 표는 공개된 KIC 정보와 일반적인 투자기관 업무 구조를 바탕으로 한 추정이며, 내부 업무 방식과는 다를 수 있다.

| 업무 | 오래 걸리는 이유 | 자동화 여지 |
| --- | --- | --- |
| 해외 사모·대체투자 실사 | 수백 페이지 재무·법률 문서를 사람이 교차 검증 | 높음 |
| **실소유 구조 파악** | 다단계 지분 관계를 여러 소스에서 수작업 추적 | **높음 (본 기획의 메인)** |
| 운용사 평가 | 이력·평판·성과를 여러 곳에서 취합 | 중간 |
| 투자심의 자료 작성 | 여러 시스템의 데이터를 한 문서로 정리 | 중간 |
| **보유 자산 이벤트 모니터링** | 뉴스·공시를 상시 확인하고 원인 분석 | **높음 (보조 모듈)** |

판단과 책임이 필요한 투자 결정, 현지 실사 판단, 운용사 관계 관리는 사람의 몫으로 남긴다. 자동화 대상은 자료 수집·대조·정리 단계다.

## 3. 타깃 사용자와 사용 시나리오

타깃은 해외 투자의 실사와 사후 모니터링을 담당하는 실무자로 확정했다. 개인투자자용 범용 서비스는 이번 범위에 넣지 않는다.

| 사용자 | 지금 하는 일 | 이 도구로 달라지는 점 |
| --- | --- | --- |
| 투자운용 실무자 | 투자 후보의 지배구조와 소유 관계를 수작업으로 확인 | 소유 그래프와 "확인 필요" 목록을 바로 받는다 |
| 투자관리(리스크) 담당 | 보유 자산의 이상 이벤트를 뉴스·공시에서 직접 찾아 원인 분석 | 원인 후보를 근거 문서와 함께 받는다 |

**사용 시나리오**

1. 실무자가 대상 기업명(또는 사업자번호·LEI)을 입력한다.
2. 에이전트가 소스를 골라 호출하며 상위 소유 관계를 재귀적으로 추적한다.
3. 소유 그래프가 그려지고, 모든 연결에 근거 문서 링크와 기준 시점이 붙는다.
4. 확인하지 못한 구간은 "공개 정보로 확인 불가"로 표시하고 사람 검토 목록으로 따로 모은다.
5. 실무자가 검토 목록을 확인한 뒤 결과를 투자심의 자료에 쓸 수 있는 형태로 가져간다.

## 4. 솔루션 개요

메인 기능은 지배구조 역추적이고, 이벤트 원인 추적은 같은 근거 체계를 공유하는 보조 모듈이다.

**메인: 지배구조 역추적**

- **입력**: 기업명, 사업자번호, LEI 중 하나.
- **출력**: 소유 그래프. 모든 연결에 근거 문서(페이지 포함)와 기준 시점이 붙는다.
- **불확실성 표시**: 확인되지 않은 연결은 다른 색으로 구분하고, 사람이 검토할 항목을 목록으로 분리한다.
- **종착점 구분**: "최종 연결 모회사"와 "공시상 확인된 개인·재단"을 구분해 표기한다. 둘을 같은 말로 쓰지 않는다.
- **구조 이상 감지**: 순환출자·상호출자가 보이면 따로 표시한다.

**보조: 이벤트 원인 추적**

- 보유 자산에서 이상 이벤트(대주주 변동, 공시 정정, 급격한 주가 변동 등)가 생기면 관련 공시와 뉴스를 묶어 원인 후보를 제시한다.
- 원인을 단정하지 않고, 후보마다 근거 링크를 붙인다.
- 대주주 변동처럼 소유 구조와 관련된 이벤트는 메인 기능을 다시 호출해 지배구조를 재추적한다.
- 실사 이후 모니터링 단계에서 쓰는 용도로 포지셔닝한다.

## 6. 데이터 소스와 역추적 로직

공시 하나에 의존하지 않고, 여러 공개 소스를 법인 식별자로 조인해 최상위까지 올라가는 구조다. GLEIF 외 소스의 접근 조건은 일반 지식 기준이므로 구현 전에 API 조건과 약관을 확인한다.

| 소스 | 제공 정보 | 역할 | 한계 |
| --- | --- | --- | --- |
| DART(OpenDART) | 최대주주·특수관계인 지분, 타법인 출자, 해외 종속기업 | 한국 상장사 출발점 | 해외 법인 구조는 잘 나오지 않음 |
| [GLEIF](https://apify.com/nexgendata/gleif-lei-entity-resolution) | 직접·최종 연결 모회사 LEI | 글로벌 법인 연결 | 각 법인의 자기 보고에 의존, 약 35%는 모회사 미보고 사유가 기록됨 |
| SEC EDGAR | 10-K 자회사 목록(Exhibit 21), 13D/13G 5% 이상 보유자 | 미국 법인 | 미국 상장·보고 대상에 한정 |
| 영국 Companies House | PSC(실질적 지배 인물) | 영국 법인, 개인 종착점 | 영국 등록 법인에 한정 |
| OpenCorporates | 여러 국가 법인 등기 집계 | 보조 조회 | 무료 호출 제한 가능 |
| ICIJ Offshore Leaks | 역외 법인 일부 | 참고 단서 | 과거 유출 데이터라 최신성 낮음 |
| 문서(LPA·PPM 등) | 펀드 구조, 지배 조항 | 레지스트리에 없는 SPV·펀드 | LLM 추출 후 사람 검토 필수 |

GLEIF의 모회사는 연결재무제표를 작성하는 최상위 법인, 즉 회계상 모회사다. 실질 소유자와 같지 않으므로 결과 화면에서 "최종 연결 모회사"로 따로 표기한다 ([GLEIF 설명](https://www.gleif.org/newsroom/blog/connect-the-corporate-dots-globally-with-the-legal-entity-identifier-a-progress-report-on-collecting-data-on-who-owns-whom)).

**역추적 로직**

1. 입력(이름·사업자번호·LEI)을 법인 식별자로 정규화한다. 이름 매칭 확신도가 낮으면 자동으로 넘어가지 않고 사람에게 확인을 요청한다.
2. 한국 상장사면 DART에서 최대주주와 특수관계인 지분을 가져온다.
3. 최대주주가 법인이면 그 법인으로 이동해 같은 과정을 반복한다. 해외 법인은 GLEIF로 상위 관계를 찾고, 미국 법인은 SEC EDGAR, 영국 법인은 Companies House로 보강한다.
4. 개인, 공익재단, 지배주주 없는 분산 소유, 공개 데이터의 끝 중 하나에 닿으면 그 지점에서 멈춘다.
5. 순환출자·상호출자를 만나면 표시하고 같은 경로를 다시 돌지 않는다.
6. 모든 연결에 출처 문서와 기준 시점을 저장한다.

## 7. 범위 전략

이번 공모전에서는 미국·영국 법인을 깊게 구현하고, GLEIF 기반 글로벌 얇은 커버는 확장 설계로 이 문서에 기록해 둔다. 실무자의 신뢰는 범위의 넓이보다 개인 종착점까지 근거를 보여주는 깊이에서 나온다고 판단했다.

| 구분 | 1단계: 미국·영국 심화 | 2단계: GLEIF 글로벌 얇은 커버 |
| --- | --- | --- |
| 상태 | **이번 공모전 구현 범위** | 설계만 기록, 구현은 후속 |
| 대상 법인 | 미국·영국 법인 + 한국 상장사 | GLEIF에 LEI가 있는 전 세계 법인 |
| 주요 소스 | DART + GLEIF + SEC EDGAR + Companies House | GLEIF Level-2 중심 |
| 도달 깊이 | 개인·재단까지 (공시·PSC 기준) | 최종 연결 모회사(회계상)까지 |
| 강점 | 실질 소유 추적 깊이, 근거 문서 풍부 | 지역 커버리지 |
| 한계 | 지원 지역이 제한적 | 개인 종착점 불가, 모회사 미보고 법인 다수 |

**확장 방식**

- 1단계의 GLEIF 모듈을 그대로 재사용하고, 소스 라우터에 국가별 도구를 추가하는 방식으로 2단계에 접근한다.
- 지원하지 않는 관할의 법인을 만나면 임의로 추정하지 않고 "미지원 관할"로 표시한 뒤 GLEIF 기반 결과만 제공한다.
- 발표와 데모에서는 현재 지원 범위를 화면에 명시해 과장된 인상을 주지 않는다.

## 8. 신뢰성 설계와 한계

이 도구의 신뢰는 "모든 걸 안다"가 아니라 "어디까지 아는지 정직하게 보여준다"에서 나온다.

**신뢰성 설계**

- **감사 추적**: 소유 그래프의 모든 연결에 출처 문서, 페이지, 기준 시점을 저장하고 화면에서 바로 열 수 있게 한다.
- **확신도 3단계**: 확인됨 / 추정 / 확인 불가로 구분해 표시한다.
- **사람 검토 목록**: 추정·확인 불가 연결을 모아 실무자가 우선순위대로 확인하게 한다.
- **LLM 역할 제한**: 문서에서 조항·지분 정보를 추출하는 데만 쓴다. 지분율 같은 수치는 원문에서 가져온 값만 표시하고, 모델이 추론한 값은 확정 결과로 내보내지 않는다.
- **기준 시점 명시**: 정정 공시를 반영하고, 결과마다 기준일을 표시한다.

**한계 (공개 정보 기준)**

- 케이맨·BVI 같은 일부 관할은 등록 정보가 비공개라 그 구간에서 추적이 끝난다. EU도 2022년 EU 사법재판소 판결 이후 일반 공개가 제한된 것으로 알고 있으나, 현재 상태는 구현 전에 확인한다.
- 종착점이 개인으로 나와도 실명이 비공개인 경우가 많다. 이때는 단정하지 않고 "추가 확인 필요"로 끝낸다.
- GLEIF의 모회사 정보는 법인 자기 보고에 의존하고, 약 35%는 미보고 사유가 기록돼 있다.
- 공시 지연과 정정으로 결과가 실제와 어긋날 수 있다.
- 소스별 이용 약관과 호출 제한은 구현 전에 확인해야 한다.

## 9. 데모 시나리오

실제 상장사 데이터로 세 가지 사례를 연속해서 보여준다. 대상 기업은 아직 정하지 않았고, 선정 기준만 먼저 정했다.

| 사례 | 선정 기준 | 보여줄 것 | 대상 기업 |
| --- | --- | --- | --- |
| A. 단순 구조 | 최대주주가 개인 또는 소수 법인 | 기본 추적 로직, 연결별 근거 링크 | 미정 |
| B. 복잡 구조 | 대기업 집단 계열사, 미국·영국 해외 법인 보유 | 다단계 추적, DART → GLEIF → SEC·Companies House로 소스 전환, "확인 불가" 표시 | 미정 |
| C. 이벤트 연동 | 대주주 변동 공시가 있는 기업 | 이벤트 감지 → 원인 후보 → 지배구조 재추적 | 미정 |

**발표에서 보여줄 비교**

- 같은 기업을 수작업으로 추적했을 때와 도구로 추적했을 때의 소요 시간을 나란히 보여준다.
- 시간 수치는 구현 후 직접 측정한 값만 쓴다. 추정치는 넣지 않는다.
- 화면 한쪽에 현재 지원 범위(미국·영국·한국)를 고정 표시한다.

## 10. 차별점과 기대효과

차별점은 "결과를 더 많이 보여주는 것"이 아니라 "결과마다 근거와 확신도를 붙여서 실무자가 그대로 믿고 쓸 수 있게 하는 것"이다.

**차별점**

- **소스를 잇는 흐름**: 국내 공시, 글로벌 법인 식별자, 해외 등기, 계약 문서를 하나의 추적 흐름으로 연결한다.
- **근거 중심**: 모든 연결에 출처와 기준 시점을 붙이고, 모델의 추론 값은 확정 결과로 내보내지 않는다.
- **불확실성 공개**: 확인하지 못한 구간을 감추지 않고 사람 검토 목록으로 넘긴다.
- **실무 맥락**: 해외 자산을 운용하는 기관의 실사와 모니터링 흐름에 맞춰 설계한다.

**기대효과**

- 실소유 구조 확인에 드는 시간 단축. 폭은 구현 후 실측해서 제시한다.
- 다단계 구조에서 생기는 확인 누락 감소.
- 실사 이후 모니터링에서 소유 변동과 이벤트를 같은 근거 체계로 추적.

**리스크와 대응**

- **소스 이용 약관과 호출 제한**: 구현 전에 확인한다. GLEIF 사이트에는 LEI 데이터 이용 약관과 AI 이용 약관이 따로 있어서, 에이전트 호출 방식이 허용되는지도 함께 본다.

- **공개 정보로 닿지 않는 구간**: 한계로 명시하고 검토 목록으로 넘긴다.
- **문서 추출 오류**: 원문에서 가져온 값만 표시하고 사람 검토를 거친다.
